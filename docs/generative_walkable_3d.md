# 生成・隙間なく歩ける 3D — 設計メモ

目標: 1地点（将来は複数）から、**隙間なく歩き回れる 3D 空間を生成AIで補完して作る**。
既存の mesh＋WASD＋衝突判定ビューワーにそのまま乗る形（出力はテクスチャ付きメッシュ）。

## 採用方針（推奨: C を第一歩 → A へ発展）

確立手法に沿う：
- **C = 単一パノラマ生成補完**（PanoDreamer / 3D Pano Inpainting 系）
  単一 equirect の「カラー＋360°深度」を作り、遮蔽縁を生成インペイントしてメッシュ化。
- **A = 生成補完ループ**（Invisible Stitch / Text2Room 系）
  新視点をレンダ→穴を生成インペイント→深度→融合 を反復し、シーンを growth。

C の部品はそのまま A に再利用できる。まず C を実装する。

## C の処理パイプライン

入力: 1 視点（lat/lng）。

1. **360°カラー（equirect）**: 既存の `equirect.py` / `panorama.py` で全周カラーを生成（Street View
   キャッシュ済み画像を再利用）。
2. **360°深度（一貫）**: equirect を透視タイルに分割し DA3 で深度推定 → equirect 深度へ統合
   （タイル境界は重なりでブレンド）。＝既存 DA3 を 360 深度推定器として使う。
3. **RGBD → メッシュ**: equirect の各画素を方位＋深度で 3D 化（球面逆投影）。視点を原点に。
4. **遮蔽縁の生成補完（キモ）**:
   - 深度の不連続（前景の縁＝オクルージョン境界）を検出。
   - 縁の「背後側」にカラー穴＋深度穴を作り、**LaMa でカラー補完**、**深度は背景側へ外挿/補完**。
   - 補完した RGBD を 3D 化して**縁の裏に詰め物ジオメトリを追加** → 横にずれても背後が見える。
5. **出力**: テクスチャ付きメッシュ glb。既存ビューワーで歩ける。

## 既存資産の再利用

| 必要 | 既存 |
|---|---|
| 360°カラー | `app/equirect.py`, `app/panorama.py`（パノラマビューワー用に既にある） |
| 深度推定 | `app/depth_da3.py`（DA3。透視タイルで使う） |
| 生成インペイント | `app/segment.py: inpaint_masked`（LaMa、実装済み） |
| メッシュ化/整列/水平化/間引き | `app/reconstruct_da3.py` のヘルパー群 |
| 歩行ビューワー | `frontend components/SceneViewer.tsx`（mesh＋衝突） |
| 画像キャッシュ | `app/streetview.py`（API課金削減・実装済み） |

新規実装は主に **(2) 360深度の統合** と **(4) 遮蔽縁の検出＋背景インペイント＋詰め物生成**。

## マイルストーン

- C1: equirect カラー＋360深度 → 球面メッシュ（補完なし）。歩けるが遮蔽は穴。
- C2: 遮蔽縁の検出＋LaMaカラー補完＋深度外挿で詰め物生成 → 隙間が埋まる。
- C3: パラメータを左パネルに露出、検証ハーネス(verify/)でGIF比較。
- （A: 複数視点で render→inpaint→depth→fuse ループへ拡張）

## リスク / 注意
- 360深度の一貫性（タイル統合の段差）。重なりブレンド＋スケール合わせで対処。
- 生成インペイントは「推測」。遮蔽が大きいほど嘘が増える（の旨をUIに明示）。
- GPU: DA3＋LaMa を順に使う（同時ロードは _free_cuda で回避、実装済みパターン）。
- 1視点は原点付近のみ歩ける。広く歩くなら A（複数視点 growth）が必要。
